# Web 面板

运行 `vla-web --root "$VLA_ROOT"`；只看界面可使用 `--demo`。服务监听本机，启动页面本身不连接设备，创建真实会话才启动 ROS。模型 Python 3.12 与 ROS Python 3.10 分开运行。

Franky worker 必须使用含 `CartesianImpedanceTracker` 且实际链接 **libfranka 0.19.0** 的独立解释器，由 `transport.worker_python` 或 `FRANKY_PYTHON` 指定；两者都未设置时当前回退到 `/usr/bin/python3`，但仍必须通过版本/API 检查。启动前可运行不连接硬件的 `--check-only`，步骤见 [Franky 环境](FRANKY_ENVIRONMENT.md)。缺少 tracker 或加载其他 libfranka 版本会拒绝会话启动，不会自动安装或修复环境。

采集与部署按「配置 → 运行 → 结束」组织。首次打开先确认现有会话；无会话时显示宽版配置总览，桌面双列、小屏单列，分为任务与记录、Franka 与输入设备、相机、模型与推理（仅部署）和默认折叠的高级环境。底部操作栏保持可见，可检查配置或启动会话；检查结果、错误和连接提示共用反馈区域。检查／启动请求期间锁定重复操作，明确失败后保留输入供修改。

创建成功或发现现有运行会话即进入工作台，初始化期间显示「启动中」，不等待相机首帧。顶部摘要显示任务、机械臂、输入源、输出位置与部署模型，左侧只放会话操作（按控制／回合／标注／故障与结束分组，软件暂停和成功保存单独着色），整列吸顶、超出屏幕时在列内滚动；右侧依次是部署控制模式、相机、遥测，以及待命时使用的采集姿态库、阻抗参数与输入诊断。顶栏随页面滚动，不遮挡左列。页面底部的会话日志按到达顺序累积命令结果和后端事件（时间为浏览器接收时间，重连前已有的条目记为「—」，最多保留 500 条），自动跟随最新一条；向上翻阅时暂停跟随，可一键复制。日志只在当前浏览器页面内保留，刷新后从服务端最近的快照重新开始。状态栏按运行状态着色：记录中显示红色指示灯，故障时整栏标红；这些颜色只反映遥测，不改变控制权。「查看配置」打开同一份表单的只读抽屉；小屏全屏显示，Tab 在抽屉内循环，Escape 或关闭按钮退出并恢复按钮焦点。只有运行工作台可拖动左右分栏，采集／部署分别记忆列宽；配置页与抽屉不改变列宽偏好，数据处理页保持独立布局。

暂停、保存、故障和连接中断不会退出工作台或解锁配置。启动请求响应丢失时，页面通过现有会话查询确认结果；在只收到空状态或上一会话状态时继续锁定，避免尚在服务端执行的请求被重复提交。服务端确认结束后保留最终状态、已有回合／帧数、错误和最近事件；点击「配置下一会话」才返回配置并沿用参数。当前页面忽略已处理结束会话 ID 的重复消息，新会话 ID 正常接入；刷新页面重新查询服务端状态。

阶段切换约 260ms、抽屉滑入约 220ms，操作按钮不等待动画结束；系统开启「减少动态效果」时关闭动画与位移。刷新重连直接呈现已知阶段。页面切换、抽屉开关和列宽调整不发送控制命令，也不重启会话。

采集页支持单／双臂 × GELLO／Gamepad；统一使用 Franky worker 的 TCP 绝对目标，旧 ROS 关节阻抗仅作为显式 legacy 配置。设备编辑器显示相机型号与 SDK 序列号，可选 side 相机；工作空间配置、Normal/Fast、恢复竖直／初始姿态、critical、阶段标注、保存／丢弃和故障恢复由公共 ROS 后端执行。完整状态监控为 50D／100D，按单位选择显示；相机预览目标 30 FPS，过期图像会标记。

两种采集输入源共用 Franka／夹爪、相机角色、任务和输出目录表单；切换 GELLO／Gamepad 保留共同配置与各自已填写的参数。GELLO 串口／校准仅在 GELLO 下显示，TCP 工作空间设置适用于采集／部署的全部输入源，设备映射和运动参数由采集 YAML 配置。单双臂各自保留硬件草稿；单臂提交不携带隐藏的右腕相机选择。

真实会话由独立 Franky worker 独占机械臂，ROS 只管理输入、协调器和外设。只有明确启用控制并完成复位确认后，输入设备才会改变目标。暂停会停止 tracker，故障会撤销控制权，必须显式恢复并再次启用；不能把“会话待命”理解为正在主动保持位姿。

Gamepad 默认恢复已验证旧单臂路线的 `joy_node` 原始布局（每臂 YAML 的 `gamepad.input_layout: raw_joy`）：LX/LY 为轴 0/1，RX/RY 为轴 3/4，LT/RT 为轴 2/5；扳机松开为 +1、全按为 −1。左摇杆前后／左右仍对应基座 X／Y，A/Y 降低／抬高。右摇杆沿实测工具轴控制，保留旧映射及工具 XY 内 −45° 修正（`right_stick_rotation_deg: -45`）；X/B 绕工具 Z 轴旋转。LB（4）切换快慢速、RB（5）切换记录阶段、View／Back（6）返回初始位置并摆正、Menu／Start（7）保持当前位置并摆正、R3（10）保持位置与倾斜、仅绕基座 Z 将水平朝向恢复为零。Web、终端、单双臂使用同一解析配置。若显式选择 `standard_sdl`，入口为 `game_controller_node`，轴序和按钮使用该布局的固定规则，不自动猜测布局。

每次显式启用人工控制／接管时捕获初始实测 XYZ。View 返回该 XYZ，Menu 保持按下时实测 XYZ；两者均恢复逻辑 TCP 的基座朝向 `diag(1,−1,−1)`，即逻辑 Z 沿基座 −Z、逻辑 X 沿 +X、逻辑 Y 沿 −Y，yaw=0。逻辑 TCP 与物理 TCP 共用原点，轴向与法兰平行；worker 内部用实测 `F_T_EE` 旋转将逻辑目标转换为硬件目标，反馈执行逆变换。实际安装绕工具 Z 为 −45° 时，逻辑竖直 yaw=0 对应硬件 TCP yaw=+45°，action／observation 不携带此安装偏置。R3 保持 XYZ 与倾斜，仅绕基座 Z 恢复逻辑 yaw=0；逻辑 X 水平投影退化时使用逻辑 Y 确定朝向。三个快捷键只在按下沿触发，通过同一 30 Hz 循环限速接近目标；完成要求实测位置误差不超过 0.5 mm、姿态误差不超过 2°，30 秒未到达则故障。推杆、ABXY 或任一夹爪扳机会阻止／取消返回；暂停、故障和输入过期保持也会取消，不自动续接。同时按下时优先 R3、其次 View、最后 Menu。RB 的记录阶段语义本轮未改为旧单臂 Critical 区间。

持续推杆时，从上次参考位姿积分；刚松开的平移方向一次性收回到当前实测坐标。姿态按实测工具的已校准输入轴，对参考相对实测的旋转向量去掉刚释放分量，保留其余分量；不做欧拉角逐项相减。随后固定保持这个新参考，不在每次中立输入时跟随实测漂移。部分松杆不取消其余方向的输入；纯姿态输入保持 TCP 目标 XYZ（工作空间限制仍生效）。参考更新仍受 worker 的步长限制，实际停止还受阻抗和机械动态影响。

手柄消息默认超过 `gamepad_hold_timeout_s=0.10` 秒未更新时，下一可提交时隙停止积分，把参考一次性收回实测位姿并保持，夹爪停止且不执行过期按钮事件。300 ms 内恢复新消息可从保持参考继续，不补积分；超过 `gamepad_joy_timeout_s=0.30` 秒锁存故障，重连后须显式恢复并启用。短暂输入等待期间继续发送保持目标，但跳过训练记录并建立 segment 缺口。启用／接管仍要求中立且输入年龄不超过 100 ms。GELLO 采样期限独立为 `gello_sample_timeout_s=0.20` 秒；Franky 目标流／请求 100 ms 和状态期限不放宽。

工作台「输入诊断」可在待命时查看原始轴、按钮和解码速度；运行时显示参考／实测误差、工作空间裁剪，以及 `input_hold`、保持和故障期限。`linear_velocity`／`angular_velocity_tool` 是原始消息的解码结果；`input_hold=true` 时不按这些旧速度推进。纵轴无反应时先比较原始轴、解码速度、目标和裁剪，不用反复启用机械臂猜测映射。

映射、快捷键、Fast 和松杆行为使用 `human_input.version: 8` 控制指纹，包含输入期限。`action` 为实际接受的绝对逻辑 TCP 目标，实测状态及 worker 实际参考使用相同的 `flange_aligned_tcp_v1` 坐标约定并独立记录；硬件 TCP、硬件参考及安装变换另行保留，只有匹配 ACK 才形成有效执行记录。使用新数据目录；不改写旧数据／checkpoint 指纹绕过校验。已有会话不会热更新，从新进程启动后生效。

GELLO 使用成功串口采样的时间和序号，100 Hz 发布检查只发送新样本，不提高串口波特率或伪造采样率。关节和夹爪值同帧传入 collector；重复、倒序和过期消息不能刷新输入新鲜度。输入中断触发原有超时和故障流程。GELLO FK 将关节转换为 TCP 参考，输入缓存修复不替代实机工具标定与阻抗调试。

这次跟踪修复改变了控制指纹；旧指纹的数据集不能直接续录，旧控制契约模型也不能直接部署。请使用新数据目录，保留原数据与模型，按当前契约重新准备训练产物；不要手动改写元数据绕过校验。软件离线／模拟验证不等于实机跟踪或重力补偿已验收。

采集相机只在「采集相机 · 角色与设备」编辑，优先级为页面明确选择 → 硬件 JSON → 采集 YAML；「使用硬件／YAML 默认」清除当前相机角色的页面覆盖。自定义 JSON 不会被页面覆盖；运行中展示启动快照并锁定编辑。部署在「相机」分组编辑硬件配置中的相机角色，自定义 JSON 模式仍在文件中配置。

姿态库位于 `runtime/web/poses.json`，保存 TCP 位姿与设备／工具／坐标系标识，不保存夹爪。恢复要求无故障待命、输入中立；启用工作空间限制时起终点均须在范围内。全部 tracker 显式准备确认后读取实测起点，只建立一次计划，完整保留记录中的目标朝向，不执行摆正。位置沿起终点直线、姿态沿最短旋转路径，共用五次平滑进度；起止参考速度为零。默认参考上限为 0.10 m/s、0.45 rad/s，同时服从会话速度和 worker 单步限制，最短时长 0.3 秒。计划仅在现有 30 Hz 循环且目标通道可用时推进，等待 ACK 冻结进度，恢复后不补发。参考到达终点且实测误差不超过 3 mm／2°才完成，60 秒超时停止；暂停、输入变化、故障或控制权变化取消并清除计划，不自动续接。双臂未选中臂保持起始参考，夹爪不恢复。状态显示参考进度、实测误差、实际耗时和“等待实测到位”。这里保证参考直线与同步，不代表实际 TCP 严格直线或已经实测提速。旧 Franky 记录保留原样；旧 `/EE` 与新 `/TCP:flange_aligned_tcp_v1` 坐标框架不匹配，禁止直接恢复，需要在新会话重新记录。更换工具或移动基座后须重新核对姿态记录。

数据处理页离线浏览视频和数值，筛选完整回合、状态字段和导出动作空间。跨空间数据须显式确认派生语义；预览可选择 absolute／chunk_relative 并指定 chunk 起点帧，输出仍为绝对数据。Demo 下数据处理也会生成真实的离线导出文件，源数据不修改。

部署页自动读取 checkpoint 动作契约，在监控中显示动作空间、训练表示与控制器状态；运行中锁定配置。VLA／RLT／自动模式按 checkpoint 能力开放，GELLO／Gamepad 人工接管均由同一 Franky TCP 阻抗协调器处理。工作台显示阻抗参数，并可通过 worker IPC 调整刚度；失败会进入故障，不能自动恢复运动。Web 不管理在线训练任务。

部署工作台的「控制模式」从左到右为「人工控制 / VLA / RLT / 分类头自动」，取代原来的「接管 / 归还策略」切换按钮。先选择「人工控制」，再点「启用控制」，即可用 GELLO／Gamepad 在不录制的情况下调整位置；点「开始回合」才开始记录，并继续保持人工控制。Gamepad 启用和开始回合前须松开输入；单双臂输入和实测状态都必须有效。录制前的摆位不会写入回合，也不会启动策略推理。

回合中选择「人工控制」明确接管，选择具体策略明确归还；重复点击当前模式不切换控制权。未录制时从人工切到策略会停止摆位并回到待命，需要再次「启用控制 → 开始回合」才执行策略。选择模式不自动启用控制；软件暂停、保存、故障、存储阻塞和队列耗尽后仍需按现有规则手动处理。「当前状态 / 实际控制来源」与所选模式分别显示，选中人工不等于正在运动。「人工控制」仅是 ROS 控制权选择，不是发给模型的新推理模式。

浏览器关闭不会关闭独立 runner。结束会话前须保存或丢弃回合；用户主动暂停撤销控制权，并沿用丢弃当前未保存回合的交互约定。队列耗尽／存储阻塞走独立停止路径，保留回合并等待手动处理，不复用丢弃入口。软件暂停不能替代现场硬件急停。主题、布局、离线图表、运行日志和相机缓存与硬件生命周期相互独立。

动作、时间与故障契约见 [ROS 动作契约](ROS_ACTION_CONTRACT.md)，恢复操作见 [工作流](WORKFLOWS.md#执行耗尽与保存恢复)。当前结果使用 [自动化验收](ACCEPTANCE.md) 生成；[Web 历史记录](archive/WEB_VALIDATION.md)仅用于追溯旧版本。

浏览器回归可用 `VLA_PYTHON=/path/to/existing/model/python bash scripts/test.sh tests/web/test_session_ui.py -q`。测试使用已有 Firefox（可设置 `VLA_FIREFOX`），临时浏览器配置、模拟设备及短路径隔离 Demo 根目录；不下载浏览器或连接硬件。缺少浏览器会明确跳过，不算验证通过。普通 Web 回归运行 `bash scripts/test.sh tests/web -q`，同样使用模型 Python 环境。

## Franky worker 环境与调参

首次启动前在仓库根目录执行 `/usr/bin/python3 scripts/install_franky_worker.py`。Web 和终端默认使用持久环境 `runtime/franky/current/bin/python`（libfranka 0.19.0）；`transport.worker_python`、`FRANKY_PYTHON` 可以依次覆盖。Web“检查配置”执行与实际启动相同的无硬件预检，失败时不启动硬件。来源锁文件、解释器隔离和安装说明见 [Franky 环境](FRANKY_ENVIRONMENT.md)。

机械臂由独立 worker 唯一控制，ROS 负责外设和协调器；collector 在 worker 与外设均 ready 后启动。TCP 绝对位姿是统一动作空间，Gamepad 松杆按释放方向一次性收回实测参考后保持，GELLO FK 和模型策略更新同一个阻抗 tracker。

配置页首次初值来自所选 YAML，可编辑后通过“检查配置”确认，启动请求将显式覆盖传入 worker 和记录契约。工作台区分草稿、已提交值与当前有效值：失焦、遥测刷新、抽屉和重连不会覆盖草稿；点击“应用阻抗参数”只提交变化项。等待期间仍可编辑，旧请求确认不会清除后来修改；“恢复当前有效值”主动丢弃草稿。下一会话保留上次确认的参数和未应用修改，不再被 YAML 初值覆盖；同一浏览器按机械臂配置／YAML 路径保存参数偏好，刷新页面或重启 Web 后仍保留（清除站点存储会移除偏好）。已有会话的有效值以 worker 遥测为准，浏览器偏好仅作启动草稿，不代表已经应用；不自动修改 YAML 或旧会话的初始配置记录。

调参沿用现有命令接口，按 Web command ID 对应的 worker request ID 确认，期间冻结输入积分和目标接受；暂停、停止和控制权切换优先，迟到确认不得恢复控制。刚度变化调用 `set_gains()`，未变化的结构字段不会触发重建，无变化请求不重启 tracker。回合开始快照及异步审计事件保留有效参数和变更。平移刚度上限 1200 N/m、旋转刚度上限 80 Nm/rad，平移/旋转裁剪下限分别为 0.005 m / 0.02 rad。结构参数修改会停止并重建 tracker，任一臂失败会停止全部机械臂。连接恢复和参数查询不会恢复运动，需显式恢复后再次启用控制。运行前的离线检查不能证明 FCI 连通性、负载设置或实际运动安全。

当前采集和部署共用单个 30 Hz 应用控制循环，人工输入更新、动作接受、Franky 目标提交和记录关联在同一回调中完成。界面操作与故障会撤销旧代次；不等待下一模型推理。独立 worker 保持目标流超时保护和底层 1000 Hz 阻抗控制。输入设备可按自己的频率采样，采集不会为等新相机帧而重发旧控制目标，也不会把同一次曝光重复写为新帧。

## 单个应用控制循环

采集、部署和姿态恢复统一使用单个 30 Hz 回调，异步 IPC 最多一条在途目标，无待发目标队列。等待确认时冻结人工积分和记录，恢复后不补算；策略按当前真实时隙取动作。Franky 保持独立 1000 Hz 阻抗闭环，固定 wheel/libfranka 0.19.0。新会话只接受 Franky/TCP，旧独立 tracking rate 和 IK 执行参数明确报错。

启用先准备全部 tracker；停止、故障、恢复后须显式启用。目标请求／流默认 100 ms、通信／状态 500 ms，健康查询不能代替目标确认。运行调参暂停目标，匹配请求确认才结束等待，代际变化使迟到确认失效。worker 通信失败有界关闭，不自动恢复运动。

相机偶发缺帧跳过整条记录，连续过期超过 `sync_tolerance_ms` 才停控。提交时冻结数据，匹配 IPC v2 确认后记录；实际参考和应用时间写入审计。缺帧和 IPC 等待形成 slot／segment 缺口，训练和 Replay 不跨缺口。旧指纹的 checkpoint 需使用匹配的新数据训练，不做静默转换。详见 [动作契约](ROS_ACTION_CONTRACT.md)。

### Gamepad 速度默认值

普通档单轴满输入：XY 0.03 m/s、Z 0.015 m/s、倾斜 0.225 rad/s、工具 Z 旋转 0.45 rad/s。Fast 恢复旧版仅平移 ×5 的行为，0.3 秒完成倍率过渡；单轴 XY/Z 为 0.15/0.075 m/s，平移合速度上限 0.16 m/s。旋转与夹爪不随 Fast 加速，角速度合量上限 0.45 rad/s。适用于新启动的单双臂采集与部署人工控制。

GELLO 和策略直接更新 TCP 参考，不经过这些 Gamepad 速度限制。共用 Franky `max_step=0.03 m`、`max_step_rad=0.10 rad` 保持原值：它们限制每次参考更新，并非机械臂实际速度。工作空间开关按会话配置、夹爪速度保持原配置；仅 Gamepad 消息期限按上述保持／故障两级处理。速度参数参与控制指纹，旧指纹的数据／checkpoint 不会自动与新配置混用。

默认阻抗现为平移 **1100 N/m**、旋转 **65 Nm/rad**（此前 1000／50），用于尝试减小跟踪误差及松杆收回的 action 跳变量；零空间刚度、误差裁剪、目标步长、力矩变化率及增益时间常数保持原值。更高刚度也增加接触反力，不能保证消除回收跳变，实机负载、标定与跟随效果仍待现场验证。新默认从新进程／会话生效；已有 YAML 显式覆盖和 Web 参数草稿优先，以工作台 worker 已确认值为准。运行中需主动应用参数，不自动修改已有会话。

纯 XYZ 人工输入在没有姿态快捷键、角度通道刚释放或输入过期保持时，保持上次绝对姿态参考；实测姿态偏移不会逐帧写回中立角度通道。固定目标不代表实际 TCP 严格保持姿态：笛卡尔阻抗允许跟随误差，平移加速、负载／重心标定、旋转刚度和机械动态可能影响实际姿态。用诊断中的 `reference_tcp`、`measured_tcp` 与 `rotation_error_rad` 判断，rot6d 是旋转矩阵前两列，不是六个独立角度；关节／肘部姿态变化也不等于末端朝向变化。排查时先在相同路径下比较 Normal／Fast，再固定其他参数对照旋转刚度；若静止仍有明显偏差，应先核对物理 TCP、工具负载与重心标定。安装朝向换算只改变坐标表达，不能消除物理跟随误差。

## 工作空间与续采

YAML `control.workspace_limits_enabled` 默认为 `true`；Web“启用 TCP XYZ 工作空间限制”可显式覆盖，启动后锁定，作用于 Gamepad、GELLO、策略、快捷键及姿态库恢复。关闭时保留有限的 XYZ 范围和页面草稿，控制投影、Gamepad 积分、姿态库起终点检查和保存校验统一停止应用 XYZ 范围；有限数值、SO(3)、机器人自身关节限制、碰撞配置、步长和故障保护继续生效。不开大范围或无穷大伪装关闭。

开关实际值写入数据元数据、`execution_projection.workspace_limits_enabled` 与控制指纹；NumPy／Torch 训练动作投影使用相同开关，仅 TCP XYZ 裁剪可关闭，关节空间限制仍保留。既有元数据未声明时按开启解释；这不代表旧控制指纹可兼容续采或部署。

“数据集模式”明确选择新建／续采，HTTP 仍提交布尔 `resume`。续采时切换输入源、状态刷新及重连保持所填目录；点击“使用推荐路径”才主动替换。检查结果显示规范化目录、已有回合数及不兼容原因。启动仍严格校验字段、控制指纹与工作空间模式／范围；同契约追加新回合，非空目录不允许按新建覆盖，不通过改写旧元数据续采。

逻辑 TCP 使用实测安装旋转，未硬编码 ±45°。运行中安装变换变化会停止并要求新会话。GELLO FK 使用相同原点和逻辑轴；手柄在换算角速度及松杆投影基底时保留原有物理方向。姿态库、策略、记录与动作投影共用逻辑参考，禁止只改目标、不改反馈。工具／控制指纹包含坐标约定和原始安装变换，旧数据集、旧 checkpoint 或外部部署的 TCP 契约不匹配时明确拒绝，不通过重写旧元数据兼容。
