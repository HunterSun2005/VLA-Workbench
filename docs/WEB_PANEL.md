# Web 面板

运行 `vla-web --root "$VLA_ROOT"`；只看界面可使用 `--demo`。服务监听本机，启动页面本身不连接设备，创建真实会话才启动 ROS。模型 Python 3.12 与 ROS Python 3.10 分开运行。

采集页支持单／双臂 × GELLO／Gamepad，采集前选择关节／TCP 控制与记录。设备编辑器显示相机型号与 SDK 序列号，可选 side 相机；工作空间配置、Normal/Fast、恢复竖直／初始姿态、critical、阶段标注、保存／丢弃和故障恢复由公共 ROS 后端执行。完整状态监控为 50D／100D，按单位选择显示；相机预览目标 30 FPS，过期图像会标记。

姿态库位于 `runtime/web/poses.json`，保存 TCP 位姿与设备／工具／坐标系标识，不保存夹爪。恢复要求无故障待命、输入中立、目标在工作空间内；使用公共协调器的 pose 控制权，输入变化或超时取消。旧 Franky 记录可以保留，但身份和坐标框架不一致时禁止直接恢复。更换工具或移动基座后须重新核对姿态记录。

数据处理页离线浏览视频和数值，筛选完整回合、状态字段和导出动作空间。跨空间数据须显式确认派生语义；预览可选择 absolute／chunk_relative 并指定 chunk 起点帧，输出仍为绝对数据。Demo 下数据处理也会生成真实的离线导出文件，源数据不修改。

部署页自动读取 checkpoint 动作契约，在监控中显示动作空间、训练表示与控制器状态；运行中锁定配置。VLA／RLT／自动模式按 checkpoint 能力开放，GELLO／Gamepad 人工接管均由同一协调器处理。Web 不管理在线训练任务。

浏览器关闭不会关闭独立 runner。结束会话前须保存或丢弃回合；暂停撤销控制权，当前未保存回合会丢弃。软件暂停不能替代现场硬件急停。主题、布局、离线图表、运行日志和相机缓存与硬件生命周期相互独立。

动作、时间与故障契约及待实机验收见 [ROS 动作契约](ROS_ACTION_CONTRACT.md)。历史测试记录在 `docs/web/VALIDATION.md`，不代表当前版本实机已验收。
